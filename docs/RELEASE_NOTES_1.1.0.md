## 本次修复

### 强制覆盖后台密码，实时生效

修复前：在后台修改密码，重启服务后被 `.env` 里的旧密码覆盖回去，白改一场。
根因是配置与数据库都想当权威，没做仲裁。

现在引入 `admin_password_env_fp` 指纹：
- `.env` 的 `ADMIN_PASSWORD` **没变** → 以数据库为准，后台改的密码保得住
- `.env` 的 `ADMIN_PASSWORD` **变了** → 以 `.env` 为准，运维改配置依然立即生效
- 两处都没配 → 拒绝登录，不退化成空口令

### JWT的失效机制

修复前：改完密码，旧会话的 JWT 依然有效，刷新页面还是登录状态，
看起来像“密码没生效”。

现在 JWT 里带上密码指纹 `pv` 字段：
- 密码一改，**此前签发的所有令牌立即失效**，无需重启、无需黑名单
- 前端改密成功后同步清除本地令牌并返回登录页
- 全局 401 自动登出，不再停在“看着还登录着”的假状态

### 额度查询接口

新增 `GET /credits` 与 `GET /v1/credits`，用 API Key 自证即可查询自己的额度，
无需管理后台 JWT

返回字段：

| 字段 | 含义 |
| --- | --- |
| `total_usage` | 已用额度 |
| `total_granted` | 额度上限 |
| `total_available` | 剩余额度 |
| `usage_percent` | 已用百分比 |
| `unlimited` | 是否无限额 |

顶层与 `data.` 下各有一份，兼容 `data.total_usage` 这类取值路径。

安全边界有意收窄：只返回**当前 Key 自己**的数字，不涉及账号池；
无效与已停用 Key 统一返回 401，不给探测者区分依据；
查询不写入 `usage_logs`，避免客户端轮询推高已用额度。

### 无限额不再显示空白

RikkaHub 等客户端用 JSON 表达式取值，取到 `null` 会转成空字符串，界面直接一片空白。
现在无限额 Key 的 `total_granted` 与 `total_available` 返回 `999999`，不再是 `null`。

### 修复服务端导出

服务器上没有官方客户端加密能力时，`client` 格式导出必定失败，
且错误信息让人以为是坏了。

现在：
- 导出弹窗默认选中「系统明文备份」，该格式无需任何密钥，必然可用
- 选择加密格式失败时（409）**自动回退明文备份重试**，并提示原因
- 单账号导出同样自动降级
- 注：该方法会使导出文件明文显示，请注意隐私泄露

## 安装与升级

- Windows：下载 `WorkBuddy2API-1.1.0-windows-x64.exe`，关闭旧程序后运行新版；
  沿用原数据目录可保留账号与配置。
- Android：下载 `WorkBuddy2API-1.1.0-android-arm64.apk` 覆盖安装，
  签名与上一正式版一致，保留应用数据。
- 服务器源码部署：备份数据库与 `.env` 后更新源码，重启服务即可；
  本次改动涉及 `admin/security.py`、`admin/server.py`、`admin/static/`、
  `admin/routers/credit_balance.py`（新增）与 `desktop/version.json`。

## 已知Bug

- 服务器环境缺少 Node.js 与 WorkBuddy 桌面端，无法获取 `X-Device-Token`
  设备指纹。普通对话不受影响，但签到、成长任务等敏感请求可能被上游
  以 `11128`（非法调用渠道）拒绝。
- 上游未返回实际积分消耗时可能使用估算，本地统计不替代上游账单。
